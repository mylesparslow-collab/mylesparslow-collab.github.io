The right tool for each job

This portfolio is about using AI well in general, not one product. Here is which tool did which part of each project. Most projects use more than one.

Conflion

Built with: Claude Code, including the research, pilot pack, animated pitch and every firm area.
Runs on: a model on the firm's own hardware through Ollama or any OpenAI-compatible server (default Qwen 2.5 14B Instruct), plus a separate local statistical model for hit ranking.

RSC Tool

Built with: Claude Code. The crew job tracker began as a ChatGPT and Codex draft that Claude Code rewrote and tested.
Runs on: small local models (for example Llama or Qwen), chosen so it runs on a modest desktop.

Win your case ASAP

Built with: Claude Code.
Runs on: Claude, inside the user's own Claude account, with a choice of Opus, Sonnet or Fable. Deadlines and quote checks are plain code.

Byzantium

Built with: Claude Code, one long session.

Cat songs and music videos

Ring Studio

Built with: Claude Code.
Runs on: no AI model for the ring itself: optics, geometry and pricing are plain code. Try-on uses Google's MediaPipe hand-tracking model, running in the browser.

How I work with AI

Rules I bring to every project

Write the system before the thing

A story bible before the novel, a 16-section prompt before the screenplay, a walkthrough of how the work is really done before the app. The system is what makes the result repeatable.

The model drafts, code decides

In business software the AI reads and suggests, while prices, totals and matching are computed in code, and a person approves every change.

Ship the whole arc

A product is not done at the demo. Tests, a walkthrough, a pilot pack, and notes for the next AI session all ship with it.
