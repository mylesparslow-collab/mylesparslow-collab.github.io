Field guide · October 2026

Run AI on your own machine, and know what to expect.

A starter guide to running open models such as Qwen, Gemma, gpt-oss and Llama on an ordinary desktop or laptop. It covers how much memory you need, which tools to install, which models to try, and when a local model is the right choice and when it isn’t.

Figures come from the llama.cpp project, Hugging Face model repos, tool documentation and published benchmarks, each linked where it is used. Anything calculated rather than measured is marked as an estimate. This space moves quickly, so check version-specific details before relying on them.

01 · The short version

Eight things to know before you install anything

Each is explained, with sources, further down.

  1. Memory decides what fits

    A model’s file size is roughly the memory its weights need. Add room for context and a gigabyte or two of overhead.

  2. Memory bandwidth decides how fast

    Each generated word reads the active weights once, so speed tracks bandwidth more than raw compute.

  3. Start at 4-bit

    Q4_K_M is the usual default: about a third of the size of 16-bit with a small, measured quality cost. Below 4-bit, quality drops quickly.

  4. Start with Ollama or LM Studio

    Both get a model chatting in minutes and offer a local API your other apps can call. Move to llama.cpp when you want control.

  5. Mixture-of-experts models are the CPU-friendly ones

    A 30B model with 3B active generates like a small model but still needs the full file in memory.

  6. Check the licence

    Qwen, Gemma 4, gpt-oss, Ministral and Granite are Apache 2.0. Llama uses its own community licence with conditions.

  7. Local trails the frontier by months

    Epoch AI measures the best open models at about four months behind closed ones, and models that fit one consumer GPU lag more.

  8. Local is strongest for private, repeatable, narrow jobs

    Extraction, classification, search over your own documents and offline use are where it earns its place.

02 · Will it fit?

The memory maths, without the jargon

Three numbers add up: the weights, the context cache, and a little overhead. Quantization is how you shrink the first one.

Weights: parameters × bits ÷ 8

A model with 8 billion parameters at 16 bits per weight needs about 16 GB. Quantization stores each weight in fewer bits. The llama.cpp project says memory and disk requirements are currently the same, so the size of the downloaded file is about the memory the weights will occupy (llama.cpp quantize README). Rule of thumb: add 1 to 2 GB on top.

QuantizationBits per weightSize of an 8B modelQuality vs full precision
Q8_08.507.95 GiBPractically identical (same top token 97.7% of the time)
Q6_K6.566.14 GiBNear-lossless (96.0%)
Q5_K_M5.705.33 GiBVery close
Q4_K_M4.894.58 GiBSmall loss (91.9%). The usual default.
Q3_K_M4.003.74 GiBNoticeable: error roughly triples versus Q4_K_M
Q2_K3.162.95 GiBPoor (71.1%). Only if nothing else fits.

Sizes and bits per weight are from the llama.cpp quantize README (Llama 3.1 8B). Quality figures are agreement with the full-precision model on Llama 3 8B from the llama.cpp perplexity README, which warns they are not comparable across different models. AMD’s FAQ suggests at least Q6 for coding and Q8 where you want near-lossless results (AMD).

Sizing advice from a quantizerBartowski, a widely used GGUF uploader, suggests choosing a file 1 to 2 GB smaller than your GPU’s VRAM. For maximum quality, add system RAM and VRAM together and apply the same rule (model card).

Context: the part that grows with long chats

The model keeps a cache of everything in the conversation so far. Its size is 2 × layers × KV heads × head size × context length × bytes per value. For Llama 3.1 8B at full precision that is about 0.5 GB at 4K context, 4 GB at 32K and 16 GB at 128K, worked out in this write-up (a secondary source; the arithmetic checks out).

  • Ollama can store the cache at 8-bit (about half the memory, “very small loss in precision”) or 4-bit (about a quarter, “small-medium loss”) by setting OLLAMA_KV_CACHE_TYPE. It needs Flash Attention, which Ollama enables where supported (Ollama FAQ).
  • Ollama’s default context depends on your VRAM: 4K under 24 GiB, 32K from 24 to 48 GiB, 256K above that (docs). If a long document seems to be “forgotten”, the default context is the first thing to check.
  • In llama.cpp the flags are --cache-type-k and --cache-type-v.

Mixture-of-experts: fast, but not small

A mixture-of-experts (MoE) model contains many specialist sub-networks and uses only a few for each word. Qwen3-30B-A3B has 30.5B parameters but 3.3B active, with 8 of 128 experts used per token (model card). gpt-oss-20b has 21B total and 3.6B active and runs within 16 GB; gpt-oss-120b has 117B total and 5.1B active and fits on one 80 GB GPU (model card). Speed follows the active parameters, but all of them must be stored, so Qwen3-30B-A3B at Q4_K_M is still an 18.6 GB file.

Because so few parameters are active, MoE models are the best fit for machines without a big GPU. llama.cpp can keep the always-used layers on the GPU and put the experts in system RAM with --cpu-moe or --n-cpu-moe N (offload guide).

03 · How fast will it be?

Speed follows memory bandwidth

Generating each word means reading the active weights from memory once. Peak speed is roughly bandwidth divided by the bytes read per word, and real numbers come in lower (explainer). Reading your prompt, by contrast, is bound by compute.

CPU only

Usable for small models. One aggregator reports about 5–8 tokens/s for a 7B at Q4 on dual-channel DDR4 and 11–13 on DDR5, and 3–4 on a laptop (source, a lower-quality secondary site, so treat these as rough ranges). A MoE model is the best choice here.

Big unified-memory machines

AMD’s Ryzen AI Max+ 395 and NVIDIA’s DGX Spark both offer 128 GB of unified memory (256 and 273 GB/s respectively). Hardware Corner measured gpt-oss-120b at 34.1 tokens/s on Strix Halo and 38.6 on a Spark, against 70.8 on an M3 Ultra, and priced them at roughly $1,500–2,000 and $4,000+ (benchmarks, NVIDIA specs).

AMD and Intel GPUs

llama.cpp supports CUDA, AMD HIP, Vulkan, Intel SYCL and Apple Metal (README). Ollama needs ROCm v7 for AMD cards, with Linux support broader than Windows, and also offers Vulkan for other GPUs (GPU docs). Unsupported AMD cards can sometimes work through an override variable, but that is unofficial. NVIDIA remains the smoothest path.

What is “good enough”?

Reading speed is about 5 tokens a second, so anything above 10 feels live in chat. Agents and long documents are where slow hardware hurts, because the model reads far more than it writes.

Ports and licences are from each project’s own README or docs, checked October 2026. Docker Model Runner, AMD Lemonade and Microsoft Foundry Local are also worth a look; I couldn’t confirm their details against official docs.

Things that changed recently

  • llama.cpp has a new llama command and installer in its README, alongside the older llama-server binary (llama.app).
  • llama-server’s documented default port is now 9931, not 8080. Docker examples still map 8080, and third-party guides still say 8080, so read the line it prints at startup.
  • Ollama on Apple Silicon can run on MLX, announced as a preview in March 2026 and needing more than 32 GB of unified memory (Ollama).
  • Continue.dev was discontinued after Cursor acquired it in June 2026 (repo). VS Code now has its own bring-your-own-model feature (see below).

Beware

  • KoboldCpp’s README warns that koboldcpp.com is a phishing site. Use the GitHub releases page.
  • Ollama’s optional :cloud models run on Ollama’s servers, not your machine. If privacy is the point, avoid those tags (a local-only mode exists: OLLAMA_NO_CLOUD=1, see the FAQ).
  • Open WebUI’s licence is not an OSI open-source licence. Fine for most uses, but read it before you build a product on it.
05 · First run

A model chatting in five minutes

Two routes. Pick the first unless you already know you want the second.

Ollama

Install from ollama.com, or on macOS and Linux:

curl -fsSL https://ollama.com/install.sh | sh
ollama pull gemma4:e2b
ollama run gemma4:e2b

Type /bye to exit. The model is served at http://localhost:11434, and http://localhost:11434/v1/ speaks the OpenAI API (any API key will do locally). Steps from the quickstart; the compatibility page lists what is supported.

llama.cpp

Install with the project’s script, Homebrew or winget, then let it download a model from Hugging Face:

curl -LsSf https://llama.app/install.sh | sh
llama cli -hf ggml-org/Qwen3.5-0.8B-GGUF
llama serve -hf ggml-org/Qwen3.5-0.8B-GGUF

The last line starts a server with a web UI (port 9931 per the current docs). Alternatives: brew install llama.cpp or winget install llama.cpp, then the classic llama-server -m model.gguf. From the README and install guide. I haven’t confirmed that llama-server -hf behaves identically to llama serve -hf.

Try a tiny model firstA 1–4B model downloads in a minute and proves your setup works. Then move up a size at a time until speed or memory stops you.

07 · Choosing a model

Where to look and what to check

Where to browse

The Ollama library shows tags, sizes, context and capability badges (vision, tools, thinking). LM Studio’s catalog filters GGUF and MLX but doesn’t show RAM needs. Hugging Face lets you filter for GGUF files.

Read the model card

Check the licence, context length, languages and intended use. Phi-4’s card, for example, says it is “not designed for multilingual use”. Llama’s custom terms are the main licence trap: they require attribution and restrict very large companies (Llama 3.1 terms).

Pick instruct, not base

Base models complete text; instruct (chat) models follow instructions. Beginners want instruct. Prefer official uploads, then well-known quantizers such as Unsloth, whose docs also warn that quants below UD-Q2_K_XL aren’t suitable for tool calling (Unsloth).

Leaderboards

LMArena ranks by human votes, and Artificial Analysis publishes open-versus-closed comparisons. Treat any ranking as a shortlist: a model that wins on general benchmarks may still lose on your task.

Test on your own task

Collect 10 to 20 real examples and run them through two or three candidates. Hamel Husain’s evals FAQ is a good guide to doing this properly.

Mind the context setting

A model advertising 256K context will not use it unless your tool allows it, and each extra token costs memory (see section 02).

08 · Local or cloud?

When local wins, and when it doesn’t

Local models are not a cheaper copy of the frontier. They are a different tool.

Local tends to win on

  • Privacy. Ollama states it doesn’t see your prompts or data when you run locally, and by default it listens only on your own machine (FAQ). For confidential material this keeps data off third-party servers. It does not replace professional duties: the ABA’s Formal Opinion 512 warns about disclosure risks of AI tools and says informed consent can’t come from boilerplate in an engagement letter (ABA).
  • Offline use. Gemma 4’s smallest models are designed to run offline on phones and small boards (Google DeepMind).
  • Repeatable volume. Once you own the hardware, a thousand classification calls cost electricity, not tokens.
  • Control. You keep the weights. Nobody retires the model you tuned your prompts against.

Cloud tends to win on

  • Raw capability. Epoch AI estimates the best open-weight models trail closed frontier models by about four months on average since January 2026 (Epoch AI). Models that fit on one consumer GPU lag by roughly 6 to 12 months (Epoch AI, 2025).
  • The hardest tasks. Artificial Analysis’s April 2026 comparison puts the best open models at 54 on its index against 60 for GPT-5.5, with wider gaps on the hardest evaluations and more hallucination on its knowledge test. It also finds open models hold most of the best price-for-performance spots, but the top ones are far too large to run at home (Artificial Analysis).
  • Long context and big agents. Memory cost makes both expensive locally.
  • No setup. No hardware to buy, tune or keep updated.

A practical splitUse a cloud model for the hard thinking and a local model for anything private, repetitive or offline. Many tools let you point the same app at either by changing a base URL.

I couldn’t find a credible source for electricity or total hardware cost comparisons, so this guide makes no claim about when local is cheaper overall.

09 · Jobs that suit local models

Small, narrow and repeated

A local model is at its best doing one defined job reliably. Here is what that looks like, including two projects on this portfolio.

Classification and extraction

Sort emails, pull fields from documents, return a fixed JSON shape. Granite 4.1 lists classification, extraction, summarization and RAG as targets (Ollama). Both Ollama and LM Studio support structured output (Ollama).

Search your own documents

Convert text to embeddings locally, then retrieve the best passages before asking a model. Options on Ollama include nomic-embed-text (274 MB) and qwen3-embedding (0.6B to 8B, 100+ languages).

Code completion

Granite 4.1 supports fill-in-the-middle completion, and qwen2.5-coder comes in sizes from 0.5B to 32B. Note VS Code’s own local-model feature doesn’t cover inline completions.

Translation and OCR

Ollama lists translategemma (4B, 12B, 27B) and document-OCR models such as glm-ocr (library).

Conflara

A legal conflicts-search workbench built with Claude Code. It runs a model on the firm’s own hardware, so client names never leave the building. Read the case study.

RSC Tool

A small-business workbench that uses compact local models to read an inbox and return structured results on a modest desktop. Read the case study.

10 · Connect your apps

Point the tools you already use at your own server

Open WebUI

pip install open-webui
open-webui serve

Opens at http://localhost:8080 (needs Python 3.11); a Docker command is in the README. Then go to Admin > Settings > Connections. For Ollama use http://host.docker.internal:11434 when Open WebUI runs in Docker. For other servers choose Add Connection and enter the URL ending in /v1, such as http://localhost:1234/v1 for LM Studio; the key can be blank. Inside Docker replace localhost with host.docker.internal. See the connection guide.

VS Code

VS Code can use your own models without a Copilot plan: open the Command Palette and run Chat: Manage Language Models. For Ollama install the official Ollama provider extension. For other servers choose Add Models, then Custom Endpoint, and set a URL like http://localhost:<port>/v1/chat/completions with tool calling enabled (docs, announcement).

Continue, which many older tutorials use, was discontinued in 2026.

From your own code

Any OpenAI client library works if you change the base URL and pass any placeholder key.

from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="local")
reply = client.chat.completions.create(
    model="gemma4:e2b",
    messages=[{"role": "user", "content": "Summarise this in one line: ..."}],
)
print(reply.choices[0].message.content)
