A

Agent

Building with AI

Also: AI agent, agentic

A model that works in a loop: plan, use tools, check results, repeat until the task is done.

Anthropic draws a useful line: workflows follow predefined code paths, while agents let the model direct its own process and tool use. Coding agents such as Claude Code and Codex read files, run commands and fix their own mistakes over many steps.

In practice Start with the simplest thing that works. A single well-prompted call or a fixed workflow is easier to trust than an open-ended agent.

See also: Tool use, Workflow, Sub-agent, MCPSource: Anthropic: Building effective agents

Alignment

Risk, safety and trust

Also: HHH, helpful honest harmless

Making AI systems pursue the goals and values their designers and users actually intend.

Alignment covers both everyday behaviour (being helpful, honest and harmless) and the long-term research question of keeping far more capable systems safe. Techniques include RLHF, Constitutional AI and interpretability research into what is happening inside models.

In practice Day to day, alignment is why models decline some requests and why they try to follow both your words and your intent.

See also: RLHF, Interpretability, SycophancySource: Anthropic: Constitutional AI · Anthropic: Glossary

API

Using AI day to day

A way for software to call a model directly, paying per token, rather than chatting in an app.

An application programming interface lets developers send prompts and receive replies from code. The API exposes settings the chat apps hide, such as temperature, max tokens and the system prompt, and is how most AI-powered products are built.

In practice Chat subscriptions and API usage are usually billed separately, and data policies can differ between them.

See also: Token, System prompt, Data retention and training on your dataSource: Anthropic: Messages API reference

Artificial intelligence (AI)

How models work

The broad field of making computers do tasks that normally need human judgment.

An umbrella term, not a specific technology. It covers everything from chess engines and spam filters to the chatbots people mean when they say “AI” today. Most of what this glossary describes sits inside one corner of it: machine learning, and within that, large language models.

In practice When someone says “we use AI”, ask which kind. A rules engine, a trained classifier and a chatbot have very different strengths and failure modes.

See also: Machine learning, Large language model, Generative AISource: Google: Machine Learning Glossary

Attention

How models work

The mechanism that lets a model decide which earlier words matter most for the next one.

For each token, attention scores how relevant every other token in the context is, then blends their information accordingly. That is how a model knows that “it” in a sentence refers to a noun three lines back.

In practice Attention is not perfect over very long inputs. Models tend to use information at the start and end of a long prompt better than the middle, so put key instructions where they will be noticed.

See also: Transformer, Context window, Context rotSource: Vaswani et al. (2017): Attention Is All You Need · Liu et al. (2023): Lost in the middle

B

Benchmark

Building with AI

A standard public test used to compare models, such as maths, coding or knowledge exams.

Labs report benchmark scores when they release models. They are useful for broad comparison but can be gamed, can leak into training data, and may not reflect the tasks you care about.

In practice Treat benchmark tables as a shortlist, then test the candidates on your own work.

See also: EvalsSource: Anthropic: Create strong empirical evaluations

Bias

Risk, safety and trust

Systematic slants in a model’s outputs, inherited from its training data or design.

Models learn from human-written text, including its stereotypes and blind spots. Bias can show up in hiring screens, image generation, translations or whose viewpoint an answer assumes. NIST lists harmful bias among the main risks of generative AI.

In practice Don’t let a model make or rank decisions about people without human review, and test outputs across different groups.

See also: Alignment, TrainingSource: NIST AI 600-1: Generative AI Profile

C

Chain of thought

Using AI day to day

Also: CoT, step by step

Having a model work through intermediate steps before giving its final answer.

A 2022 Google paper showed that prompting a model with worked, step-by-step examples sharply improved its accuracy on maths and logic. Today many models do this reasoning on their own; see reasoning model.

In practice With a reasoning model, turn up its thinking or effort setting rather than writing “think step by step”. With a fast model, asking it to reason first can still help on multi-step problems.

See also: Reasoning model, PromptSource: Wei et al. (2022): Chain-of-thought prompting

Chunking

Building with AI

Splitting long documents into smaller passages so they can be embedded and retrieved.

A whole book is too big to embed as one vector, so it is cut into chunks, often a few hundred tokens each, sometimes overlapping. Chunk size is a trade-off: too small loses context, too large dilutes relevance.

In practice Split on natural boundaries such as headings and paragraphs, and keep the document title with each chunk.

See also: RAG, EmbeddingSource: Anthropic: Effective context engineering for AI agents

Context engineering

Building with AI

Deciding what goes into a model’s context, and what stays out, at every step of a task.

As agents run for many steps, the bigger question shifts from wording one prompt to curating everything the model sees: instructions, tool results, retrieved documents, memory and history. Anthropic frames it as finding the smallest set of high-signal tokens that gets the job done.

In practice Clear stale history, summarise long tool output, and give the model the files it needs instead of everything you have.

See also: Context window, Context rot, RAG, Sub-agentSource: Anthropic: Effective context engineering for AI agents

Context file (CLAUDE.md, AGENTS.md)

Building with AI

A file in a project that a coding agent reads automatically for standing instructions about that project.

Claude Code reads CLAUDE.md; Codex and many other agents read AGENTS.md. These files hold build commands, conventions, project structure and gotchas, so you don’t repeat them in every session.

In practice Keep it short and specific. Write what the agent would otherwise get wrong, not a general description of good coding.

See also: System prompt, Agent, SkillSource: Anthropic: Claude Code memory (CLAUDE.md) · AGENTS.md

Context rot

Using AI day to day

Also: lost in the middle

The tendency for answer quality to drop as the context gets longer or more cluttered.

Research has found that models use information at the start and end of a long input better than information in the middle, and that performance falls as irrelevant material piles up. Anthropic describes context as a finite resource with diminishing returns.

In practice In long chats, start fresh with a clean summary when answers start drifting. In documents, put the question last and the key facts where they stand out.

See also: Context window, Context engineering, AttentionSource: Liu et al. (2023): Lost in the middle · Anthropic: Effective context engineering for AI agents

Context window

Using AI day to day

How much text a model can consider at once: your prompt, files, the conversation so far and its reply.

The context window is the model’s working memory, measured in tokens. Everything outside it is invisible to the model. Windows have grown from a few thousand tokens to hundreds of thousands or a million, enough for whole books or codebases.

In practice A bigger window is not a reason to paste everything. Relevant, well-organised context beats a pile of loosely related files.

See also: Token, Context rot, Context engineering, RAGSource: Anthropic: Glossary

D

Data retention and training on your data

Risk, safety and trust

Also: privacy, data use

Whether a provider stores your conversations, for how long, and whether it may train models on them.

Policies differ by provider, product and plan, and they change. Consumer apps often have settings to opt in or out of training; business and API plans usually have stricter defaults. Anything you paste may be stored for some period.

In practice Read the current data settings for the tool you use, and follow your employer’s policy. Keep confidential client data out of tools your organisation hasn’t approved, or use a local model.

See also: Local model, APISource: NIST AI 600-1: Generative AI Profile

Diffusion model

How models work

The approach behind most image generators: start from noise and remove it step by step into a picture.

A diffusion model is trained by adding noise to images and learning to reverse it. To generate, it starts from random noise and repeatedly denoises it, guided by your text prompt, until an image appears. Stable Diffusion and many video models work this way.

In practice Image models respond to what you name, so describe what you want to see. Writing “no text” can make text more likely to appear.

See also: Generative AI, MultimodalSource: Ho et al. (2020): Denoising diffusion probabilistic models

Distillation

Running models yourself

Training a small “student” model to imitate a large “teacher” model.

Instead of learning only from raw data, the student learns from the teacher’s outputs, which carry richer information about what the teacher thinks is likely. The idea was popularised by Hinton and colleagues in 2015. Many small open models are distilled from bigger ones.

In practice Distilled models can punch above their size on the tasks they were distilled for, but may be weaker outside them.

See also: Small language model, Fine-tuningSource: Hinton et al. (2015): Distilling the knowledge in a neural network · Google: Machine Learning Glossary, generative AI terms

E

Embedding

Building with AI

Also: vector

A list of numbers that represents the meaning of a piece of text, so similar meanings sit close together.

An embedding model turns text (or images) into a vector, often hundreds or thousands of numbers long. Texts with similar meaning end up with similar vectors, even if they share no words, so “car insurance” lands near “auto coverage”.

In practice Embeddings power semantic search, recommendations, clustering and RAG.

See also: Vector database, Semantic search, RAGSource: OpenAI: Embeddings guide · Google: Machine Learning Glossary

Evals

Building with AI

Also: evaluations

Tests that measure how well a model or prompt performs on your actual task.

An eval is a set of inputs with a way to judge the outputs: exact answers, code that checks the result, or a rubric scored by a person or another model. Evals let you compare prompts or models with evidence instead of impressions.

In practice Twenty real examples from your own work, scored consistently, tell you more than any public leaderboard.

See also: Benchmark, PromptSource: Anthropic: Create strong empirical evaluations

F

Fine-tuning

How models work

Extra training on a smaller, focused dataset to specialise a model or change its behaviour.

Fine-tuning starts from a trained model and continues training on examples of the behaviour you want, such as a house writing style or a particular output format. It changes the model’s weights, unlike prompting, which only changes the input.

In practice Try better prompts, examples and retrieval first. Fine-tuning is worth it when you need consistent behaviour at scale and have hundreds or thousands of good examples.

See also: LoRA, RLHF, RAG, Zero-shot and few-shotSource: Anthropic: Glossary · Google: Machine Learning Glossary

Foundation model

How models work

A large model trained on broad data that can be adapted to many different tasks.

The term was coined by Stanford researchers in 2021 for models like GPT-3 and BERT that serve as a base for many applications. One foundation model can be prompted, fine-tuned or wrapped in tools to do customer support, coding, translation and more.

In practice Most AI products are built on a handful of foundation models. Knowing which one sits underneath tells you a lot about a product’s strengths and limits.

See also: Large language model, Fine-tuning, Pre-trainingSource: Bommasani et al. (2021): On the opportunities and risks of foundation models

G

Generative AI

How models work

AI that creates new content, such as text, images, audio, video or code, rather than only classifying or predicting.

Older ML systems mostly sorted things: spam or not spam, fraud or not fraud. Generative models produce new material that resembles what they were trained on. Chatbots, image generators like Midjourney and music tools like Suno are all generative AI.

In practice Generated content can look finished before it is right. Treat it as a strong first draft that still needs a human check.

See also: Large language model, Diffusion model, MultimodalSource: Google Cloud: Generative AI glossary · NIST AI 600-1: Generative AI Profile

GGUF

Running models yourself

The common file format for quantized models that run in llama.cpp, Ollama and LM Studio.

A single GGUF file bundles a model’s weights and the information needed to run it. File names show the quantization level, for example Q4_K_M (about 4-bit) or Q8_0 (8-bit). Hugging Face hosts thousands of them.

In practice When downloading, pick the largest quantization that fits in your memory with room to spare for context.

See also: Quantization, Ollama and llama.cpp, Local modelSource: Hugging Face: GGUF

Grounding

Using AI day to day

Tying a model’s answer to specific trusted sources, such as your documents or a web search.

A grounded answer is based on supplied material rather than the model’s memory alone, and can usually cite where each claim came from. Retrieval, web search and pasting documents into the prompt are all ways to ground a model.

In practice Ask the model to quote the passage that supports each claim. Quotes are easy to check; paraphrases are not.

See also: RAG, HallucinationSource: Anthropic: Reduce hallucinations · Lewis et al. (2020): Retrieval-Augmented Generation

Guardrails

Risk, safety and trust

Checks around a model that block or correct unsafe, off-topic or malformed inputs and outputs.

Guardrails can be rules in code, a second model that screens content, limits on which tools an agent may use, or a human approval step before risky actions. They sit outside the model, so they still work when the model is fooled.

In practice For any agent that can spend money, send messages or delete things, require a human confirmation step.

See also: Jailbreak, Prompt injection, AgentSource: OWASP: LLM01:2025 Prompt Injection · NIST AI 600-1: Generative AI Profile

H

Hallucination

Risk, safety and trust

Also: confabulation

When a model states something false or made up as if it were true.

Because LLMs generate plausible text, they sometimes invent facts, quotes, citations, statistics or code functions that don’t exist. NIST’s generative AI profile calls this confabulation. It is more likely on obscure topics, precise numbers and questions beyond the model’s knowledge.

In practice Ask for sources and check them, let the model say “I don’t know”, give it the documents to work from, and verify anything you will act on or publish.

See also: Grounding, RAG, Knowledge cutoff, SycophancySource: NIST AI 600-1: Generative AI Profile · Google Cloud: Generative AI glossary · Anthropic: Reduce hallucinations

I

Inference

How models work

Running a trained model to get an answer. Every chat message is an inference request.

Training builds the model once; inference uses it, over and over. Inference cost depends on model size and on how many tokens go in and come out, which is why API pricing is quoted per million input and output tokens.

In practice Long prompts, long documents and long answers all cost inference. Trimming what you send is the simplest way to make AI faster and cheaper.

See also: Token, Latency, TrainingSource: Google: Machine Learning Glossary, generative AI terms

Interpretability

Risk, safety and trust

Also: explainability, mechanistic interpretability

Research into what is actually happening inside a model when it produces an answer.

Models are not programmed line by line, so even their makers can’t simply read off why they did something. Interpretability researchers trace the internal features and circuits a model uses, to find errors, hidden reasoning and safety problems.

In practice A model’s explanation of its own reasoning is not guaranteed to match what happened internally. Judge answers by checking them, not by how convincing the explanation sounds.

See also: Alignment, Chain of thoughtSource: Anthropic: Tracing the thoughts of a large language model

J

Jailbreak

Risk, safety and trust

A prompt crafted to get a model to ignore its safety rules.

Jailbreaks use role-play, hypotheticals, obfuscation or long manipulative setups to talk a model past its guardrails. OWASP treats jailbreaking as a form of prompt injection. Labs patch known jailbreaks, and new ones keep appearing.

In practice If you build on a model, don’t rely on the model’s refusals alone to protect anything important. Add checks in your own code.

See also: Prompt injection, Guardrails, AlignmentSource: OWASP: LLM01:2025 Prompt Injection

K

Knowledge cutoff

Using AI day to day

Also: training data cutoff

The date after which a model’s training data stops, so it knows nothing newer on its own.

A model only knows what was in its training data. Events, prices, product versions and research after the cutoff are unknown unless the app gives the model web search or you paste the information in.

In practice For anything recent, turn on web search or supply the source. A model may confidently describe an outdated version of something.

See also: Pre-training, Grounding, RAGSource: Anthropic: Models overview

L

Large language model (LLM)

How models work

A very large neural network trained on huge amounts of text to predict what comes next.

An LLM learns to predict the next token in a sequence by reading a vast amount of text. That simple objective, at enormous scale, produces models that can write, summarise, translate, reason through problems and write code. Claude, GPT, Gemini, Llama and Qwen are all LLMs.

In practice Because an LLM generates what is plausible, not what is checked, fluent output is not proof of correct output. Verify facts that matter.

See also: Token, Transformer, Pre-training, HallucinationSource: Anthropic: Glossary · Google: Machine Learning Glossary

Latency

Using AI day to day

Also: TTFT, time to first token

How long you wait for a response. Often measured as time to first token.

Latency depends on model size, prompt length, how much the model thinks and how busy the service is. Time to first token is how quickly text starts streaming; total time depends on reply length.

In practice For interactive tools, a smaller or faster model with a tight prompt often feels better than a bigger model that is slightly smarter.

See also: Inference, Reasoning modelSource: Anthropic: Glossary

Local model

Running models yourself

Also: self-hosted, on-device

A model that runs entirely on your own computer, so your data never leaves it.

With an open-weight model and a tool like Ollama, LM Studio or llama.cpp, you can run a capable assistant offline. Local models are smaller than frontier cloud models, so they trade some capability for privacy, control and zero per-token cost.

In practice A strong choice for confidential documents, offline use and repetitive jobs. Expect to test which model size your hardware runs comfortably.

See also: Open-weight model, Quantization, VRAM, Ollama and llama.cppSource: Ollama · llama.cpp

LoRA

Running models yourself

Also: QLoRA, adapter

A cheap way to fine-tune a model by training a small add-on instead of all its weights.

Low-Rank Adaptation freezes the original model and trains a small set of extra weights. Microsoft’s 2021 paper reported cutting trainable parameters by up to 10,000 times for GPT-3 with comparable quality. LoRA files are small and can be swapped in and out.

In practice LoRA makes fine-tuning possible on a single consumer GPU. It is also widely used to teach image models a style or character.

See also: Fine-tuning, ParametersSource: Hu et al. (2021): LoRA

M

Machine learning (ML)

How models work

Software that learns patterns from examples instead of following hand-written rules.

Instead of a programmer writing every rule, a machine learning system is shown many examples and adjusts itself until its outputs match them. The result is a model: a file of learned numbers that can make predictions on new inputs it has never seen.

In practice Machine learning is only as good as its examples. Gaps or bias in the training data show up as gaps or bias in the answers.

See also: Model, Training, Neural networkSource: Google: Machine Learning Glossary

Max tokens

Using AI day to day

Also: output limit

The cap you set on how long a model’s reply can be.

An API setting that stops generation after a given number of output tokens. It protects against runaway costs, but if it is set too low a reply is cut off mid-sentence.

In practice If answers end abruptly, check max tokens before rewriting your prompt.

See also: Token, InferenceSource: Anthropic: Messages API reference

MCP (Model Context Protocol)

Building with AI

An open standard for connecting AI apps to outside tools and data, often compared to a USB-C port for AI.

Created by Anthropic in 2024 and now used across many AI apps, MCP defines how an AI client talks to “servers” that expose tools, data and prompts. Write one MCP server for, say, your calendar or database, and any MCP-compatible app can use it.

In practice Only install MCP servers you trust. A server can see what you send it and can feed instructions back to the model.

See also: Tool use, Agent, Prompt injectionSource: Model Context Protocol: Introduction

Mixture of experts (MoE)

How models work

A model split into many sub-networks (“experts”), where only a few are used for each token.

A router picks a small set of experts for each token, so a model can have a huge total parameter count while only a fraction does work at any moment. That makes it cheaper to run than a dense model of the same size. Many recent open models, including some Qwen and Llama releases, use MoE.

In practice For local use, an MoE model still needs memory for all its parameters, even though it runs at the speed of a smaller one.

See also: Parameters, VRAMSource: Shazeer et al. (2017): Sparsely-gated mixture of experts

Model

How models work

The trained artifact that takes an input and produces an output, for example GPT-5, Claude or Llama.

A model is the result of training: a large set of learned numbers plus the code that runs them. Products like ChatGPT or the Claude app wrap a model in an interface with extra features such as memory, file upload and web search.

In practice The app and the model are different things. The same model can behave differently in the app, the API and a third-party tool because each adds its own instructions and tools.

See also: Large language model, Parameters, System promptSource: Google: Machine Learning Glossary · Anthropic: Glossary

Multimodal

How models work

A model that can take in or produce more than one kind of data, such as text, images, audio or video.

Early LLMs handled text only. Multimodal models can read a screenshot, a chart, a PDF page or a photo alongside your text, and some can generate images or speech. Claude, GPT and Gemini all accept images as input.

In practice Instead of describing a chart or an error dialog, paste a screenshot. It is often faster and more accurate.

See also: Large language model, Diffusion modelSource: Anthropic: Vision · Anthropic: Models overview

N

Neural network

How models work

Also: deep learning

A model built from layers of simple connected units whose connection strengths are learned.

Loosely inspired by the brain, a neural network passes numbers through many layers. Each connection has a weight, and training nudges those weights until the network produces useful outputs. Modern language, image and audio models are all very large neural networks.

In practice “Deep learning” just means neural networks with many layers. It is the approach behind nearly every AI product you use today.

See also: Parameters, Transformer, TrainingSource: Google: Machine Learning Glossary

O

Ollama and llama.cpp

Running models yourself

Also: LM Studio

Popular free tools for downloading and running open models on your own computer.

llama.cpp is the open-source engine that runs models efficiently on ordinary CPUs and GPUs, including Macs. Ollama wraps engines like it in a simple command-line app and local API: one command downloads and runs a model. LM Studio offers a graphical alternative.

In practice Ollama’s local API lets your own scripts use a local model much as they would a cloud API.

See also: Local model, GGUF, APISource: Ollama · llama.cpp

Open-weight model

How models work

Also: open model, open source model

A model whose trained weights are published so anyone can download and run it.

Llama, Qwen, Mistral and Gemma publish their weights; GPT-5 and Claude do not. Open weights are not the same as open source: the Open Source Initiative’s definition also expects enough information about the training data and code to rebuild the model, and many open-weight licences add usage limits.

In practice Open weights mean you can run a model privately on your own hardware. Read the licence before using one commercially.

See also: Local model, ParametersSource: Open Source Initiative: Open Source AI Definition

P

Parameters (weights)

How models work

Also: weights, 7B, 70B

The learned numbers inside a model. “7B” means about seven billion of them.

Parameters are the adjustable values that training tunes. More parameters generally means more capacity to learn, but also more memory and compute to run. Model names often include the count: Llama 3 8B, Qwen 2.5 14B.

In practice Parameter count is the quickest way to estimate whether a model will fit on your computer. See the memory rule of thumb in the cheat sheet.

See also: Model, Quantization, VRAM, Open-weight modelSource: Google: Machine Learning Glossary

Pre-training

How models work

Also: base model

The first, largest stage of training, where a model learns language by predicting text at huge scale.

In pre-training, a model reads a vast corpus of text and learns to predict the next token. The result, a base model, knows a great deal but is not yet a helpful assistant: it may simply continue your text rather than answer it. Later stages turn it into a chat model.

In practice Pre-training is where a model’s general knowledge, and its knowledge cutoff, come from.

See also: Training, Fine-tuning, RLHF, Knowledge cutoffSource: Anthropic: Glossary · Brown et al. (2020): Language models are few-shot learners

Prompt

Using AI day to day

The input you give a model: instructions, questions, examples and material.

A prompt can be one line or several pages. Good prompts state the goal, give relevant context, separate instructions from pasted material, and say what a good answer looks like.

In practice The companion Prompting Field Guide covers this in depth, with 45 copy-paste prompts.

See also: System prompt, Zero-shot and few-shot, Context engineeringSource: Anthropic: Prompting best practices

Prompt caching

Using AI day to day

Reusing the processed start of a prompt across requests, so repeated context is faster and cheaper.

If many requests begin with the same long text, such as a system prompt, a document or a codebase summary, the provider can store that processed prefix and skip recomputing it. Anthropic and OpenAI both offer caching at a steep discount on cached input.

In practice Put stable material first and the part that changes last, so the cache can be reused.

See also: Inference, Context window, APISource: Anthropic: Prompt caching

Prompt injection

Risk, safety and trust

Hidden instructions in content a model reads (a web page, email, file) that hijack what it does.

OWASP ranks prompt injection as the top risk for LLM applications. Direct injection comes from the user typing it; indirect injection hides in outside content the model processes, such as white text on a web page telling an agent to email your files somewhere. There is no complete fix yet.

In practice Be most careful when an AI can do three things at once: read your private data, read untrusted content, and send data out. Simon Willison calls this the lethal trifecta.

See also: Jailbreak, Agent, MCP, Tool useSource: OWASP: LLM01:2025 Prompt Injection · Simon Willison: The lethal trifecta

Q

Quantization

Running models yourself

Also: Q4, Q8, 4-bit

Storing a model’s numbers at lower precision, such as 4-bit instead of 16-bit, so it uses far less memory.

Models are usually trained with 16-bit numbers. Quantization rounds them to 8, 5, 4 or fewer bits, cutting memory and often speeding things up, with a small loss in quality that grows as precision drops. 4-bit is a popular balance for local use.

In practice If a model won’t fit, try a lower-bit version before trying a smaller model. Going below about 4 bits usually hurts noticeably.

See also: GGUF, VRAM, ParametersSource: Hugging Face: Quantization overview

R

RAG (retrieval-augmented generation)

Building with AI

Also: retrieval

Look up relevant documents first, then give them to the model to answer from.

Introduced in a 2020 paper from Facebook AI Research, RAG pairs a retriever with a generator. The system searches a knowledge base for passages relevant to the question, adds them to the prompt, and the model answers from them. This lets a model use private or up-to-date information without retraining.

In practice Most “chat with your documents” tools are RAG. Answers are only as good as what gets retrieved, so test the search step, not just the final answer.

See also: Embedding, Chunking, Grounding, Fine-tuningSource: Lewis et al. (2020): Retrieval-Augmented Generation · Anthropic: Glossary

Reasoning model (thinking)

Using AI day to day

Also: extended thinking, thinking budget, effort

A model trained to think at length before answering, trading speed for accuracy on hard problems.

Reasoning models generate an internal chain of thought, sometimes thousands of tokens long, before they reply. Claude’s extended thinking, OpenAI’s reasoning models and Gemini’s thinking modes all expose a setting for how much to think.

In practice Use more thinking for maths, debugging, planning and tricky analysis. For quick rewrites or lookups, less thinking is faster and cheaper with little loss.

See also: Chain of thought, Inference, LatencySource: Anthropic: Extended thinking

RLHF (reinforcement learning from human feedback)

How models work

Training a model on human ratings of its answers so it becomes more helpful and better behaved.

People compare pairs of model answers and pick the better one. Those preferences train a reward model, which then steers the language model toward answers people prefer. OpenAI’s InstructGPT paper showed this made a much smaller model preferred over a far larger base model. Anthropic’s Constitutional AI uses AI feedback guided by written principles for part of this step.

In practice RLHF is why chat models follow instructions politely. It is also one cause of sycophancy, since people tend to rate agreeable answers highly.

See also: Fine-tuning, Alignment, SycophancySource: Ouyang et al. (2022): Training language models to follow instructions with human feedback · Anthropic: Constitutional AI · Anthropic: Glossary

S

Semantic search

Building with AI

Search by meaning rather than exact keywords.

Keyword search matches words; semantic search compares embeddings, so a search for “ending a lease early” can find a passage about “early termination”. Many systems combine both, called hybrid search, because exact terms such as names and codes still matter.

In practice If users search with their own words rather than your jargon, semantic search helps them find things.

See also: Embedding, Vector database, RAGSource: OpenAI: Embeddings guide

Skill (Agent Skill)

Building with AI

A folder of instructions, scripts and resources an agent loads only when a task needs it.

Anthropic introduced Agent Skills in 2025 as a way to package expertise. The agent sees only each skill’s short description until a task calls for it, then reads the full instructions, so many skills can be installed without crowding the context.

In practice If you find yourself pasting the same long procedure into chats, it is a candidate for a skill.

See also: Context file, Agent, Context engineeringSource: Anthropic: Equipping agents for the real world with Agent Skills

Small language model (SLM)

How models work

Also: small model

A language model small enough to run on a laptop or phone, usually a few billion parameters or fewer.

There is no official cutoff, but models in roughly the 1 to 15 billion parameter range are commonly called small. They are less capable on hard reasoning than frontier models, but they are fast, cheap and can run privately on your own hardware.

In practice A good fit for narrow, repeatable jobs like classifying emails, extracting fields from documents or drafting short replies, especially where data can’t leave the building.

See also: Local model, Quantization, Parameters, DistillationSource: Google: Machine Learning Glossary · Ollama

Structured output (JSON mode)

Using AI day to day

Making a model reply in an exact machine-readable format, such as JSON matching a schema.

Apps often need data, not prose. Structured output features constrain the model so its reply always matches a schema you provide, with the right fields and types, so code can use it reliably.

In practice If you are copying model output into a spreadsheet or another program, ask for a fixed format, or use the API’s structured output option.

See also: Tool use, APISource: OpenAI: Structured outputs

Sub-agent

Building with AI

A helper agent with its own fresh context, sent off by a main agent to handle one part of a job.

The main agent hands a focused task, such as searching a codebase or researching one question, to a sub-agent, which works in its own context window and returns only a summary. This keeps the main conversation clean and lets work run in parallel.

In practice Useful for big research or code exploration, where the details would otherwise flood the main context.

See also: Agent, Context window, Context engineeringSource: Anthropic: Claude Code subagents

Sycophancy

Risk, safety and trust

A model’s tendency to tell you what you want to hear: agreeing, flattering or caving when you push back.

Anthropic research found that sycophancy is common across AI assistants and is likely driven partly by human preference ratings in training, which reward agreeable answers. A model may abandon a correct answer simply because you questioned it.

In practice Ask for criticism directly, avoid signalling the answer you hope for, and be suspicious when a model reverses itself only because you objected.

See also: RLHF, Hallucination, AlignmentSource: Anthropic: Towards understanding sycophancy in language models

System prompt

Using AI day to day

Also: system message, custom instructions

Standing instructions that frame every reply, set by the app or developer rather than typed each time.

Apps use a system prompt to give the model its role, tone, rules and tools before your message arrives. Custom instructions in ChatGPT, project instructions in Claude and CLAUDE.md or AGENTS.md files in coding agents all work in a similar way.

In practice Put durable preferences (who you are, how you like answers formatted) in custom or project instructions instead of repeating them in every chat.

See also: Prompt, Context fileSource: Anthropic: Prompting best practices · Anthropic: Messages API reference

T

Temperature

Using AI day to day

A setting for randomness. Low gives focused, repeatable output; high gives more varied output.

When choosing the next token, a model weighs many candidates. Low temperature sticks closely to the most likely ones; high temperature gives less likely tokens more of a chance. Anthropic’s glossary puts it simply: higher is more creative and varied, lower is more conservative and predictable.

In practice Use low temperature for facts, extraction and code; higher for brainstorming and fiction. Even at temperature 0, outputs are not guaranteed to be identical every time. Some reasoning models fix or ignore this setting.

See also: Top-p, InferenceSource: Anthropic: Glossary · Google: Machine Learning Glossary, generative AI terms

Token

Using AI day to day

The chunk of text a model reads and writes. In English, about ¾ of a word, or 4 characters.

Models don’t see letters or words; they see tokens, which are common word pieces. “Unbelievable” might be three tokens. Context limits, speed and price are all measured in tokens. Other languages, code and unusual words often take more tokens per word.

In practice Rule of thumb: 1,000 tokens is roughly 750 English words. Token-based processing is also why models sometimes miscount letters in a word.

See also: Tokenizer, Context window, InferenceSource: OpenAI: What are tokens and how to count them · Anthropic: Glossary

Tokenizer

Using AI day to day

The tool that splits text into tokens before a model sees it.

Each model family has its own tokenizer with its own vocabulary, so the same text can be a different number of tokens in Claude, GPT or Llama. Public tokenizer tools let you paste text and see exactly how it is split.

In practice Use a tokenizer tool when you need to estimate cost or check whether a long document will fit.

See also: TokenSource: OpenAI: What are tokens and how to count them

Tool use (function calling)

Building with AI

Also: function calling, tool calling

Letting a model call outside functions, such as search, a calculator or an API, and use the results.

The developer describes available tools; the model decides when to call one and with what arguments; the app runs it and returns the result; the model continues. This is how chatbots search the web, run code or book a meeting.

In practice Tools turn a model from something that talks into something that acts, which is useful and also raises the stakes. See prompt injection.

See also: Agent, MCP, Structured outputSource: Anthropic: Tool use overview · OpenAI: Function calling

Top-p (nucleus sampling)

Using AI day to day

Another randomness setting: only consider the most likely tokens that together reach probability p.

With top-p of 0.9, the model picks from the smallest set of tokens whose probabilities add up to 90%, cutting off the long tail of unlikely words. It was introduced to make generated text less repetitive without becoming incoherent.

In practice Adjust temperature or top-p, not both. Most people never need to touch top-p.

See also: TemperatureSource: Holtzman et al. (2019): The curious case of neural text degeneration

Training

How models work

The process of adjusting a model’s parameters by showing it examples, usually at great expense.

During training a model makes predictions, measures how wrong they are, and nudges its parameters to be a little less wrong, billions of times over. Training a frontier model takes months on thousands of specialised chips. Using the finished model is called inference.

In practice Your chats do not retrain a model in real time. Whether a provider may use your conversations for future training depends on your settings and plan; see data retention.

See also: Pre-training, Fine-tuning, Inference, Data retention and training on your dataSource: Google: Machine Learning Glossary · Anthropic: Glossary

Transformer

How models work

The neural network design behind modern LLMs, built around a mechanism called attention.

Introduced by Google researchers in the 2017 paper “Attention Is All You Need”, the transformer processes a whole sequence at once and lets every token weigh its relationship to every other token. It trains efficiently on modern chips, which is why it scaled into today’s models. The “T” in GPT stands for transformer.

In practice You rarely need the internals, but transformers explain two everyday facts: why there is a context window limit, and why longer inputs cost more.

See also: Attention, Context window, Large language modelSource: Vaswani et al. (2017): Attention Is All You Need

V

Vector database

Building with AI

Also: vector store

A database built to store embeddings and quickly find the ones closest to a query.

Given a question’s embedding, a vector database returns the stored chunks whose embeddings are most similar. Dedicated products exist, and many ordinary databases now offer vector search as a feature.

In practice For a small project, a few thousand chunks fit comfortably in a simple local store. You don’t need specialised infrastructure to start.

See also: Embedding, Semantic search, RAGSource: Google Cloud: Generative AI glossary

VRAM (and unified memory)

Running models yourself

Also: GPU memory

The memory a model must fit into to run fast, on a graphics card or in a Mac’s shared memory.

A model runs quickest when all its weights fit in GPU memory. Apple Silicon Macs share one pool of unified memory between CPU and GPU, which lets them run larger models than a similarly priced PC graphics card. Memory needed also grows with the context length you use.

In practice Rough sizing: parameters × bits ÷ 8. A 7B model at 4-bit is about 3.5 GB of weights; budget around 5 GB in total.

See also: Quantization, Parameters, Local modelSource: Hugging Face: Quantization overview · llama.cpp

W

Workflow (vs agent)

Building with AI

Also: prompt chaining

A fixed sequence of model calls and code, designed in advance, rather than letting the model decide each step.

Examples include prompt chaining (draft, then critique, then revise), routing (classify, then send to the right prompt) and running several calls in parallel. Workflows are predictable and easy to debug.

In practice If you can write the steps down in advance, build a workflow. Reach for an agent when the steps genuinely depend on what the model finds.

See also: AgentSource: Anthropic: Building effective agents

Z

Zero-shot and few-shot

Using AI day to day

Also: in-context learning, one-shot

Zero-shot: just ask. Few-shot: include a few worked examples of the answer you want.

The GPT-3 paper showed that large models can pick up a new task from a handful of examples placed in the prompt, without any retraining. Examples are one of the most reliable ways to control format and tone.

In practice Use two to five varied examples. If they all look alike, the model will copy their quirks.

See also: Prompt, Fine-tuningSource: Brown et al. (2020): Language models are few-shot learners · Google: Machine Learning Glossary, generative AI terms

Key terms

  • Token The chunk of text a model reads and writes. In English, about ¾ of a word, or 4 characters.
  • Context window How much text a model can consider at once: your prompt, files, the conversation so far and its reply.
  • System prompt Standing instructions that frame every reply, set by the app or developer rather than typed each time.
  • Temperature A setting for randomness. Low gives focused, repeatable output; high gives more varied output.
  • Hallucination When a model states something false or made up as if it were true.
  • Knowledge cutoff The date after which a model’s training data stops, so it knows nothing newer on its own.
  • Reasoning model A model trained to think at length before answering, trading speed for accuracy on hard problems.
  • Grounding Tying a model’s answer to specific trusted sources, such as your documents or a web search.
  • RAG Look up relevant documents first, then give them to the model to answer from.
  • Embedding A list of numbers that represents the meaning of a piece of text, so similar meanings sit close together.
  • Tool use Letting a model call outside functions, such as search, a calculator or an API, and use the results.
  • Agent A model that works in a loop: plan, use tools, check results, repeat until the task is done.
  • MCP An open standard for connecting AI apps to outside tools and data, often compared to a USB-C port for AI.
  • Fine-tuning Extra training on a smaller, focused dataset to specialise a model or change its behaviour.
  • Parameters The learned numbers inside a model. “7B” means about seven billion of them.
  • Quantization Storing a model’s numbers at lower precision, such as 4-bit instead of 16-bit, so it uses far less memory.
  • Open-weight model A model whose trained weights are published so anyone can download and run it.
  • Prompt injection Hidden instructions in content a model reads (a web page, email, file) that hijack what it does.
  • Sycophancy A model’s tendency to tell you what you want to hear: agreeing, flattering or caving when you push back.
  • Multimodal A model that can take in or produce more than one kind of data, such as text, images, audio or video.

Five habits

  1. Verify anything you will act on or publish.
  2. Paste the source instead of trusting memory.
  3. Start a fresh chat when answers drift.
  4. Never mix private data, untrusted content and outbound tools.
  5. Test on your own examples, not leaderboards.
